# Contributing

Thank you for contributing. Start from `main` using a descriptive branch such as `feat/jira-components` or `fix/creation-result`. Use concise conventional commits (`feat:`, `fix:`, `docs:`, `test:`).

Before opening a pull request, run `npm run lint`, `npm run typecheck`, `npm run test`, and `npm run build`. Add or update tests for behavior changes and document externally visible behavior. Keep credentials out of commits and do not bypass validation or provider boundaries.

Pull requests should explain the product reason, implementation, test evidence, and relevant screenshots. Maintainers may ask for smaller, separately reviewable changes.
